## 数据模型约定

### 用户隔离（关键）

- 所有业务表**必须**带 `owner_id`（批次 2 起）。
- 查询一律走 API 层注入的当前用户，强制 `WHERE owner_id = :uid`，不靠业务代码自觉。
- 共享功能尚未实现，但表结构预留：未来加 `visibility` 字段与关联表即可，不需要迁移历史数据。

### 时间戳

- 所有 `DateTime` 列一律 `timezone=True`。
- ⚠️ **SQLite 读回来的 datetime 是 naive 的**，PG 是 aware 的。任何比较前必须过
  `app.core.time.as_aware()`，否则在 SQLite 上测试通过、在 PG 上反而没事，或者反过来炸。

### 令牌

| | 存放 | 有效期 | 用途 |
|---|---|---|---|
| access token | 前端内存 | 30 分钟 | 每个请求的 `Authorization: Bearer` |
| refresh token | 前端 localStorage | 30 天 | 换新 access token；**库里只存 sha256 摘要** |

- **轮换**：每次刷新都吊销旧会话、签发新会话。旧令牌重放直接 401。
- **改密**：吊销该用户全部会话，强制所有设备重新登录。
- **设备管理**：`user_sessions` 一行 = 一台设备，可在设置页单独吊销。

## 标签体系（批次 2）

单品与搭配是**两套完全独立的标签体系**：同一张表、同一个 `owner_id`，靠 `scope` 列
（`garment` / `outfit`）隔开，互不可见。

| scope | 默认类别 |
|---|---|
| `garment` | 大类 / 小类 / 颜色 / 材质 |
| `outfit` | 季节 / 风格 / 色系 |

- 默认类别在**用户创建时播种**（注册、bootstrap 管理员、`cli.py create-user` 三处）。
  ⚠️ 不要改成「首次访问时懒加载」—— 用户删掉某个默认类别后会被重新塞回来。
- 播种前会检查该 scope 下是否已有类别，所以 `0002` 的数据迁移重复执行也安全。
- 类别 / 取值删除时**显式清理关联表**，不依赖数据库级联（SQLite 默认不强制外键）。

## 媒体文件（批次 2）

`<img src>` 带不了 `Authorization` 头，所以图片走**签名 URL**：

```
/api/media/<相对路径>?e=<过期时间戳>&s=<HMAC-SHA256(路径 + 过期时间)>
```

- 签名只绑定「路径 + 过期时间」，改动任一项即失效；过期后返回 403。
- 默认 TTL 7 天（`WARDROBE_MEDIA_URL_TTL_SECONDS`），列表接口每次返回新签名的 URL。
- 落盘结构：`<media_root>/<owner_id>/<年月>/<uuid>.<ext>`，原图**不重压**，
  另生成两档 WebP 缩略图（240 / 720 px）。
- 读取时 `resolve_key()` 拦路径穿越；上传时用 Pillow 真解一遍，伪造成图片的文本会被拒。
- 删除衣物 / 图片会连带删除磁盘文件；多文件上传中途失败会回收已落盘的部分。

## ⚠️ `expire_on_commit=False` 的坑（踩过）
`SessionLocal` 用了 `expire_on_commit=False`（async 下避免 commit 后触发懒加载）。
副作用：**commit 之后对象仍带着旧的已加载关系集合，而 `selectinload` 默认不会覆盖
已加载的集合**。表现是「改了标签 / 调了封面顺序，接口返回的还是旧数据」。

- 需要重新读的关系，必须加 `.execution_options(populate_existing=True)`（见
  `routes/garments.py::_load_garment`）。
- 关系上的 `order_by` 也只在首次加载时生效，序列化时显式再排一次更稳。

## 接口一览（批次 2）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/tags/categories?scope=` | 列类别 + 取值 |
| POST | `/api/tags/categories` | 新建类别（重名 409） |
| PATCH/DELETE | `/api/tags/categories/{id}` | 改名 / 删除（连带清关联） |
| POST | `/api/tags/categories/{id}/values` | 新建取值（重名 409） |
| PATCH/DELETE | `/api/tags/values/{id}` | 改取值 / 删除（自动解除已打标） |
| GET | `/api/garments?q=&tag_value_ids=&page=&page_size=` | 列表，`tag_value_ids` 多值取**交集** |
| POST | `/api/garments` | 新建（可带 `tag_value_ids`） |
| GET/PATCH/DELETE | `/api/garments/{id}` | 详情 / 改 / 删（删则连带清图） |
| POST | `/api/garments/{id}/images` | 多文件上传（字段名 `files`） |
| POST | `/api/garments/{id}/images/{img}/primary` | 设为封面（排到最前） |
| DELETE | `/api/garments/{id}/images/{img}` | 删单张图 + 清文件 |
| GET | `/api/media/{key}?e=&s=` | 签名取图 |

列表返回的 `cover_url` / `thumb_*_url` 都是**已签名的完整路径**，前端直接塞 `<img src>`。

## 已知取舍 / 后续加固

1. **refresh token 放在 localStorage**，理论上可被 XSS 读取。自托管单用户场景可接受。
   上 https 后建议改为 httpOnly + SameSite=Strict 的 Cookie（需同步调整 CORS 与 CSRF 策略）。
2. **X-Forwarded-For 直接信任首段**。仅在反代（Lucky / nginx）可信的前提下成立；
   若 API 直接暴露公网需要收紧。
3. 注册默认关闭。开放注册前应加邮箱验证或邀请码。

## 浏览器验收（agent-browser）

本机 Chrome 不在默认位置，**每条命令都要带**：

```bash
agent-browser open <url> --executable-path "C:/Users/openclaw/AppData/Local/ms-playwright/chromium-1243/chrome-win64/chrome.exe"
```

三个坑：

1. ⚠️ **不要把 `agent-browser` 的输出接进管道**（`| grep` / `| tail`）。daemon 会继承
   管道的写端，管道永远不 EOF，命令就永远不返回 —— 看起来像「冷启动卡死」，其实
   `open` 早就成功了。一律 `> 文件 2>&1`。
2. daemon 可能在两次工具调用之间被回收，页面变回 `about:blank`。所以**整条流程要放在
   同一次 bash 调用里**跑完。
3. 给 daemon 传 `--executable-path` 会提示 `ignored: daemon already running`，属正常。

现成的验收脚本（一次性跑完，截图落到 `out/wardrobe-shots/`）：

```bash
bash out/wardrobe-shots/run.sh    # 缩略图墙 / 筛选 / 标签管理 / 编辑器
bash out/wardrobe-shots/run2.sh   # 真实「新建衣物 + 上传图片」全流程
```

⚠️ 用 `eval` 点击元素时，选择器**必须限定作用域**。例如 `.chip-toggle` 在筛选栏和
编辑弹窗里都存在，`document.querySelectorAll('.chip-toggle')` 会先命中筛选栏那个。
